# KB증권 export 파서 스펙

> 소유: B · 최종수정 2026-08-27
> 이 문서는 **실측**으로 확인한 것과 **아직 모르는 것**을 구분해서 적는다.
> 추측을 사실처럼 적지 말 것 — 여기서 틀리면 지표·백테스트 수치가 전부 흔들린다.

## 0. 요약

KB는 화면마다 파일 포맷이 다르다. 확장자를 믿지 말고 항상 먼저 이걸 돌려라:

```bash
python tools/inspect_export.py <받은파일>              # 구조 확인
python tools/inspect_export.py <받은파일> --redact     # 공유용 마스킹 사본
```

출력의 `데이터 행` 이 0이면 화면이 틀렸거나 조회 기간이 좁은 것이다.

## 1. 확인된 사실 (실측)

### 1.1 포맷이 두 가지다

| 출처 | 실제 포맷 | 읽는 법 |
|---|---|---|
| kbsec.com 웹 | 진짜 `.xlsx` | `engine="openpyxl"` |
| H-able HTS 「엑셀로 보내기」 | **구형 `.xls` (BIFF)**, Crownix Report 생성, CP949 | **`engine="calamine"`** |

### 1.2 ⚠ HTS 의 .xls 는 xlrd 로 안 열린다

```python
pd.read_excel("da03450000.xls")                     # → struct.error: unpack requires a buffer of 2 bytes
pd.read_excel("da03450000.xls", engine="calamine")  # → 정상
```

파일의 SST 레코드가 살짝 깨져 있다. **엑셀·LibreOffice 로는 멀쩡히 열리기 때문에**
"파일은 정상인데 파이썬만 죽는" 상황이 되어 원인 찾는 데 오래 걸린다. 미리 알고 가자.

```bash
uv add python-calamine
```

### 1.3 헤더 위에 안내 행이 붙는다

HTS export 는 표 위에 제목 / `계좌번호:` / `계좌명:` / `출력일자:` 행을 붙이는데
**개수가 화면마다 다르다.** 헤더 행 번호를 하드코딩하면 안 되고,
앵커 텍스트로 찾아야 한다 (`reader.find_header_row`).

또 오른쪽에 빈 셀을 20개씩 붙여서 내보낸다 (`reader.trim_right`).

### 1.4 🚨 헤더 2행 + **레코드 2행** 화면이 있다 — 0112

가장 중요한 화면인 **0112 거래내역조회**가 이 구조다. 같은 열에 위/아래로 다른 항목이 쌓인다:

```
[헤더1] 거래일자   거래종류      수량  거래금액  정산금액  거래세 등      소득세     ...
[헤더2]            종목명        단가  수수료    펀드/신탁  농특세·부가세  지방소득세  ...

[값1]  2026/08/27  전자금융입금        10,000    10,000            0          0
[값2]                            0     0                    0          0
```

- 2열 = 위 `거래종류` / 아래 `종목명`
- 3열 = 위 `수량` / 아래 `단가`
- 4열 = 위 `거래금액` / 아래 `수수료`

**1행 = 1레코드로 읽으면 단가와 수수료가 통째로 날아간다.** 게다가 조용히 날아가서
"파싱은 됐는데 값이 이상한" 상태가 된다. 잔고 화면(0345)도 같은 패턴이다.

대응: YAML 에 `header_rows` / `record_rows` 를 선언한다. 파서가 (행오프셋, 열인덱스)로
위치를 잡는다.

```yaml
header_rows: 2
record_rows: 2
```

### 1.5 🚨 엑셀이 종목코드 앞자리 0 을 날린다

0377 의 `종목번호` 가 `035720`(카카오)인데 셀에는 숫자 `35720.0` 으로 저장돼 있다.
여기서 소수점만 지우면 **`357200`** 이라는 존재하는 다른 코드가 나온다 —
에러 없이 조용히 틀리는 유형이다. 반드시 정수로 만든 뒤 `zfill(6)`.
`kb_hts.normalize_ticker()` 가 처리한다.

### 1.6 🚨 export 파일에 개인정보가 평문으로 들어있다

HTS export 에는 `계좌번호: 394-297-826-01`, `계좌명: 홍길동` 이 셀 값으로 박혀 있다.

- **원본을 레포에 커밋하지 마라.** `.gitignore` 에 `data/raw/` 를 걸어둔다
- 팀에 공유해야 하면 `--redact` 로 마스킹 사본을 만들어 그것만 보낸다
- `fixtures/` 에 들어가는 건 전부 지어낸 값이어야 한다

## 2. 대상 화면

### 2.1 거래내역 (예수금 원장) — 현재 매핑 대상

실측 헤더 (kbsec.com 웹, 8컬럼, 시트 `Sheet0`, 0행이 헤더):

```
거래일 | 내용 | 종목명 | 수량 | 단가 | 입금/입고/매도 | 출금/출고/매수 | 예수금잔액(원)
```

매핑: `core/parser/mappings/kb_transaction_ledger.yaml`

**이 화면의 한계 3가지 — 전부 하류에 영향을 준다:**

| 한계 | 결과 | 대응 |
|---|---|---|
| 종목코드가 없다 | 엔진이 pykrx 일봉을 못 붙임 | `resolve_tickers()` 로 종목명 역매핑. 사명 변경·우선주·상폐 종목은 실패함 |
| **수수료·세금 컬럼이 없다** | 실현손익이 gross 인지 net 인지 알 수 없음 | `fee=tax=None` 으로 두고 **절대 0 으로 채우지 않는다**. §3 참조 |
| 매매·입출금·배당이 섞여 나온다 | 그대로 넣으면 거래 건수가 부풀려짐 | YAML `row_filters` 로 스킵 + 사유를 리포트에 남김 |

### 2.2 화면번호 목록 (H-able 실측)

H-able 좌측 상단 입력창이 **화면검색**이다. `거래내역` / `실현손익` 을 치면 목록이 나온다.

| 화면 | 이름 | 우리한테 쓸모 |
|---|---|---|
| **0112** | 거래내역조회 | ★ **엔진 입력의 본체.** 매수·매도 전부 나옴 |
| **0330** | 일자별실현손익(상세) | ★ **수수료·제세금 확보.** 단 청산된 건만 |
| 0377 | 종목별주문/체결집계 | **종목번호(코드)가 있음** — 종목명 역매핑을 피할 수 있는 유일한 화면 |
| 0341 | 실시간체결/미체결 | 당일만 |
| 0353 | 금일매매보고서 | 당일만 |
| 0328 / 0329 / 0355 | 기간·종목별 실현손익 | 0330 의 집계판 |
| 0502 | 입출금간편거래내역 | 매매 아님 |
| 0345 | 실시간잔고 | 스냅샷 — **거래 이력 없음** |
| 1960 | 투자패턴분석 | ⚠ §6 참조 |

### 2.3 0330 일자별실현손익(상세) — 매핑 완료

화면 캡처로 확인한 헤더:

```
매매일자 | 종목명 | 구분 | 매매구분 | 체결수량 | 체결단가 | 매수단가 |
매수금액 | 매도금액 | 수수료 | 제세금 | 실현손익 | 수익률
```

매핑: `core/parser/mappings/kb_0330_realized_pnl.yaml`

**원장 화면의 약점 3개 중 2개가 여기서 해결된다** — 수수료·제세금이 컬럼으로 있고,
매매구분이 텍스트로 직접 들어있어 판정이 단순하다. 종목코드는 여전히 없다.

⚠ **한계: 청산된 건만 나온다.** 매수만 하고 아직 안 판 종목은 이 화면에 없다.
포지션 재구성 엔진(A)은 매수 이력이 있어야 타임라인을 만들 수 있으므로 **0112 와 함께** 써야 한다.

> **0112 = 엔진 입력 (매수·매도 전부)**
> **0330 = 수수료·제세금 검산 (§3 마지막 항목의 답)**

### 2.4 쓰면 안 되는 화면

- **잔고 / 자산현황 / 0345 실시간잔고** — 시점 스냅샷이라 거래 이력이 없다. 세 번 헛짚었다
- **증명서발급 → 거래내역서** — 세무용 PDF
- **해외주식 거래내역** — pykrx 에 일봉이 없어서 엔진이 못 돌린다.
  단 **값 표기 포맷 확인용으로는 유용**하다. (화면검색 안내문에도 "간편내역 조회시 외화거래는
  조회되지 않습니다" 라고 적혀 있으니 원장 화면에서 찾지 말 것)

### 2.5 🚨 export 가 비는 가장 흔한 원인: 조회기간

0112 는 조회기간이 **당일~당일**로, 0330 은 **1주일**로 기본 설정된다.
계좌개설일까지 넓히지 않으면 거래가 있어도 빈 표가 나온다. export 전에 반드시 기간부터 늘릴 것.

## 3. 미확정 (실데이터 오면 즉시 채울 것)

| 항목 | 현재 처리 | 확인 방법 |
|---|---|---|
| 날짜 포맷 | 후보 5개를 순서대로 시도 | 실제 행 1개 |
| 천단위 콤마 | 문자열/숫자 둘 다 처리 | 실제 행 1개 |
| 음수 표기 (괄호 vs `-`) | 둘 다 처리 | 매도 또는 출금 행 |
| `내용` 컬럼 실제 표기 | `매수/매도/매입/매각` 포함 여부로 판정 | 실제 매매 행 — **`현금매수` 인지 `주식매수` 인지 확인 필요** |
| **정산금액이 gross 냐 net 이냐** | 미확정 | 매도 행에서 `단가×수량` 과 `입금액` 비교. 어긋나면 net (수수료·세금 차감 후) |

마지막 항목이 제일 중요하다. `schema.validate()` 가 0.5% 이상 어긋나면 경고를 띄우게 해뒀다.
결론이 나면 `docs/schema.md` 의 수수료 처리 규칙(A 소유)과 맞춰야 한다.

## 4. 사용법

```python
from core.parser import kb_hts

result = kb_hts.parse("data/raw/거래내역.xlsx")
print(result.report())        # 건수·기간·종목수·스킵행+사유 — 매번 눈으로 확인할 것

trades, unresolved = kb_hts.resolve_tickers(result.trades)
if unresolved:
    print("종목코드 미해결:", unresolved)   # 이 종목들은 엔진에서 제외된다
```

새 화면을 지원하려면 **코드가 아니라 YAML 을 추가한다**:

```python
result = kb_hts.parse(path, mapping_path="core/parser/mappings/kb_execution.yaml")
```

## 6. ⚠ 기획서에 영향 가는 발견 — KB 화면 1960 「투자패턴분석」

화면검색 중에 KB증권 H-able 에 **`1960 투자패턴분석`** 화면이 이미 존재하는 걸 확인했다.

킥오프 브리핑 2장에는 "증권사 AI는 정보 제공 중심이라 개인 편향 진단은 공백"이라고 적혀 있는데,
심사위원(금융보안원 + KB증권 공동주최)이 이 화면을 알고 있을 가능성이 높다.
**"이미 있는 거 아니냐"는 질문이 나올 자리다.**

대응 방향 (A가 기획서에서 정리할 것):
- 이 화면이 실제로 뭘 보여주는지 먼저 확인한다 (조회해서 캡처)
- 우리 차별점은 **진단**이 아니라 **개입 + 효과 증명**이라는 쪽으로 무게를 옮긴다.
  브리핑 2장의 기능 3개 중 ②개입 ③백테스트가 진짜 공백이다
- 오히려 "증권사도 이 방향으로 가고 있다"는 **시장성 근거**로 쓸 수 있다 (브리핑의 한투·유안타 논리와 동일)
