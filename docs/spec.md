## 5. 편향 정의와 점수 산식 [C]

각 편향: 정의 1줄 → 거래내역에서 잡는 방법 → 점수 0~100 산식 → 등급 컷 → 근거(evidence) 예시.

### 5.1 처분효과 (disposition)
- 정의: 오른 종목은 서둘러 팔고(익절), 내린 종목은 계속 버티는(손절 회피) 경향. Odean(1998) PGR/PLR 그대로 사용.
- 잡는 방법: 청산 episode 는 `realized_pnl` 부호로, 미청산 episode 는 timeline 최신 스냅샷의 `unrealized_pnl` 부호로 이익/손실 건을 가른다 (3%/-3% 같은 문턱 없음 — 부호만 봄, 문턱을 두면 그 구간 실현손익 부호가 랜덤에 가까워져 신호가 희석됨).
  - PGR = 실현이익 건수 / (실현이익 건수 + 미실현이익 건수)
  - PLR = 실현손실 건수 / (실현손실 건수 + 미실현손실 건수)
- 산식: `raw = PGR − PLR` (이론상 [-1, 1]) → `score = (raw + 1) / 2 × 100`
- 등급 컷: score < 40 안정 · < 70 주의 · ≥ 70 위험 (`api/service.py` `GRADE_THRESHOLDS`)
- evidence: 가장 빨리 판 이익실현 건 1개 + 가장 오래 버틴 손실(미실현 포함) 건 1개

### 5.2 물타기 (averaging_down)
- 정의: 이미 평가손실 상태인 종목에 추가매수하는 경향. 진입 매수 자체는 물타기가 아니다 — 진입 이후 추가매수만 센다.
- 잡는 방법: BUY 건을 `(ticker, traded_at)`으로 해당 episode 구간에 역매칭 → 진입일 매수 제외 → 매수 당일 timeline 스냅샷의 `unrealized_pnl < 0` 인 건만 카운트.
  - 최초 구현(`1aab17b`)부터 −5% 문턱 없이 손실 여부(`< 0`)만 봄 — README가 "−5% 이하"로 잘못 적혀 있던 걸 코드 기준으로 정정함(README §5).
- 산식: `raw = 손실 상태 추가매수 건수 / 전체 매수 건수` → `score = raw × 100`
- 등급 컷: 5.1과 동일
- evidence: 평가손실 상태에서 추가매수한 건 나열

### 5.3 추격매수 (chasing)
- 정의: 이미 오른 종목에 더 오를 걸 기대하고 뒤늦게 따라 들어가는 경향.
- 잡는 방법: 이미 보유 중인 종목에 대한 **같은 episode 내** 추가매수 중, 전일 종가 대비 +5% 이상 급등한 가격에 매수한 건을 카운트. 신규 진입은 비교할 전일 종가가 없어 판정 자체가 불가 — 분모(판정 가능 건수)에도 포함하지 않는다. (분모를 전체 매수로 잡으면 판정 불가 건이 섞여 왜곡됨 — §5.4 참조 버그였음.)
- 산식: `raw = 급등 후 매수 건수 / 판정 가능한 매수 건수(같은 episode 내 전일 종가 있는 추가매수)` → `score = raw × 100`
- 등급 컷: 5.1과 동일
- evidence: 급등 후 매수 건 나열 (급등률 %, 매수 시점 기준 — 그 이후 실제 수익률 아님)
- ⚠ 스키마 한계: 신규 진입 종목의 "당일 급등 후 추격매수"는 원시 시세 시계열이 없어 판정 불가 (기획서 로드맵 항목)

## 6. 브레이크 룰 [C]

각 룰: 트리거 조건(주문 시점 정보만) → 임계값 → 개입 문구 생성(LLM + 템플릿 폴백) → 가드레일(숫자 화이트리스트·금지어·타임아웃 2.5s).

- 룩어헤드 금지 원칙 명시: 판정에 쓰는 정보는 주문 시점 `as_of` 이전 데이터뿐

| 룰 | 트리거 조건 (주문 시점 정보만) | 기여 점수 (`core/rules`) |
|---|---|---|
| 추격매수 | BUY 주문 + 보유 이력 있는 종목의 timeline 최근 종가 대비 주문가가 **+5% 이상** | `MAX_CONTRIBUTION(40) × (과거 chasing score/100)` |
| 물타기 | BUY 주문 + 해당 종목 현재 평가손실 상태(`unrealized_pnl < 0`) | `MAX_CONTRIBUTION(35) × (과거 averaging_down score/100)` |
| 처분효과 | SELL 주문 + 해당 종목 현재 평가이익 상태(`unrealized_pnl > 0`) | `MAX_CONTRIBUTION(25) × (과거 disposition score/100)` |

- `risk_score` = 세 룰의 기여 점수 합 (0~100). `risk_score ≥ INTERVENE_THRESHOLD(50)` 이면 개입 팝업 표시 (`core/rules/base.py`)
- 세 룰 다 "과거 편향 점수가 높을수록 이번 주문의 위험 기여가 커진다"는 동일 구조 — 전역 가중치가 아니라 개인 실증(자기 과거 점수)에 근거를 묶어 "가중치 근거가 뭐냐" 공격을 무력화하는 설계(README §4.2)
- 추격매수 룰의 "전일 종가"는 `timeline`에 보유 이력이 있는 종목만 알 수 있다 — 신규 진입 종목은 판정 skip (metrics/chasing.py 와 동일한 스키마 한계)

**개입 문구 생성 (`core/guard`)**
- LLM: `claude-haiku-4-5` 우선 호출, 타임아웃 **2.5초**
- 폴백 조건: `anthropic` 미설치 · API 키 없음 · 타임아웃 · JSON 파싱 실패 · 검증 실패 — 전부 고정 템플릿(`core/guard/templates.py`)으로 대체
- 시스템 프롬프트로 "evidence 숫자만 사용, 투자 추천/목표가/전망 언급 금지"를 지시하고, 출력을 사후 검증(`core/guard/validator.py`)으로 한 번 더 강제:
  - **숫자 화이트리스트**: LLM 출력의 모든 숫자가 evidence 안에 존재해야 함 (없으면 폴백)
  - **금지어 필터**: "추천/매수하세요/매도하세요/목표가/손절가/적정가/전망/예상수익/오를/내릴" 포함 시 폴백
