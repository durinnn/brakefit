# fixtures/upload — `POST /api/upload` 검증용 목 데이터

실 증권사 CSV 를 아직 못 구해서, 업로드 경로(`api/service.py` `ingest_upload`)를
이 파일들로 대신 검증한다. 검증 코드는 `tests/test_upload_fixtures.py`.

> **전부 가공 데이터다. 실사용자 거래내역이 아니고, 실사용자 분포도 아니다.**
> 계좌번호·계좌명·종목명·금액은 전부 지어낸 값이다 (AGENTS.md 절대규칙 4).

| 파일 | 목적 |
|---|---|
| `standard_basic.csv` | 표준 스키마(docs/schema.md §1) 정상 경로 — ticker 포함, 국내주식 3종목, 매수 7/매도 5, `fee`/`tax` 를 일부 빈칸으로 둬서 `None` 과 `0` 이 안 섞이는지 확인 |
| `kb_0112_sample.csv` | KB증권 0112 「거래내역조회」 화면 형식(2행 헤더 + 2행 레코드) — 파서가 표준 CSV 가 아니라 KB 매핑으로 인식하는지, 종목코드가 없는 화면에서 `_fill_tickers()` 가 도는지 확인 |
| `standard_oversell.csv` | 보유수량(15주)보다 많이 판 행(20주) 1건 포함 — 엔진이 경고를 남기고 보유분까지만 계상한 뒤 계속 도는지 확인 |
| `broken_columns.csv` | 헤더가 표준·KB 어느 쪽도 아닌 파일 — 400 과 한국어 사유(시도한 형식 4가지)를 돌려주는지 확인 |

## 손검산 전제

- 기간 **2026-06-02 ~ 2026-08-13**, 종목 **005930 / 035720 / 035420** 은
  `data/cache/prices/*.parquet` 캐시 범위(2025-11-03 ~ 2026-09-03) 안이다.
  그래서 `core/synth/prices.get_daily_close()` 가 pykrx 네트워크를 안 탄다.
  기간이나 종목을 바꿀 거면 캐시부터 확인할 것.
- 단가는 캐시에 들어있는 실제 종가를 그대로 썼다. 수수료는 거래금액의 0.015%,
  매도 세금은 거래세 등 0.15% + 농특세 0.03% 로 계산했다.
  `정산금액 = 거래금액 ± 수수료 ∓ 세금` 이라 `schema.validate()` 의
  "단가×수량 vs 정산금액 0.5%" 검사를 통과한다.
- `kb_0112_sample.csv` 의 예수금 컬럼은 입금 20,000,000 원에서 시작해 정산금액을
  차례로 더한 값이다 (파서는 안 쓰지만, 사람이 표를 읽을 때 검산 기준이 된다).
- `kb_0112_sample.csv` 의 `가나다반도체` 는 존재하지 않는 종목이다. 종목명→코드
  역매핑이 실패하는 경우(사명 변경·상장폐지)를 재현하려고 일부러 넣었다.

## 알려진 한계
