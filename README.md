## 3. 무엇을 만드나

**타겟**: 2030 신규 진입 직접투자자 (모바일 MTS 채널)

**기획서 프레임**: "빚투 손실이 청년 부채 문제로 이어지는 시점에, 신규 투자자를 본인의 데이터로 보호한다"
— 소비자보호형 사회적 소구

**기능 3개 (90초 데모의 뼈대)**

| | 기능 | 내용 |
|---|---|---|
| ① | **진단** | 거래내역 업로드 → 편향 건강검진 리포트 (지표 점수 + 백분위) |
| ② | **개입** | 모의 주문창에서 위험 게이지(0~100) + 기여도 워터폴 + 과거 패턴 경고<br>("당신의 과거 추격매수 12건 평균 −18%") |
| ③ | **증명** | 브레이크를 따랐을 때의 백테스트. **회피한 손실과 놓친 이익을 함께 net으로 제시**<br>→ 반사실 가정이라는 공격 지점을 정직성·신뢰 포인트로 전환 |

**차별점**: 증권사 AI는 정보 제공 중심. 개인 편향 진단 + 주문 개입 + 효과 검증의 조합은 공백.

> ⚠ 단, KB증권 HTS 에 `1960 투자패턴분석` 화면이 **이미 존재**한다.
> KB가 공동주최사라 심사위원이 안다. "이미 있는 거 아니냐"가 나올 자리.
> → 무게 중심을 **진단**이 아니라 **개입 + 효과 증명**으로 옮길 것. [`docs/parser-kb.md`](./docs/parser-kb.md) §6 참조.

## 4. 확정된 설계 결정 (재논의 없이 진행)

1. **데이터: 업로드 단일 파이프라인.** 마이데이터 허가(자본금 50억 등) 없이 증권사 API 위임 호출은
   규제 위반 → **규제 준수 자체가 설계 차별점.** 어댑터 패턴(`TradeDataSource`)으로 확장성 입증,
   `MyDataApiAdapter` 는 명세 문서만.
2. **AI: 규칙 기반 위험 스코어(0~100) + 기여도 워터폴.** 점수 근거를 전역 가중치가 아니라
   **개인 실증**에 결속 → "가중치 근거가 뭐냐" 공격 무력화. 임계값은 개인 손익 분포 분위수로 추정.
3. **LLM은 판단이 아니라 설명 레이어.** 개인화 코칭 문구 생성에만 쓴다.
4. **ML 기각.** 지도학습은 학습 데이터 부재(합성 데이터 학습은 생성 규칙을 되배우는 순환논리).
   비지도 이상탐지는 만성 편향자에겐 편향이 '평소'라 정상으로 학습됨. → 기획서의 확장 로드맵으로만.
5. **프레임: 화이트박스 = 금융위 AI 가이드라인(설명가능성·책임성) 구현.** 기획서 전면에 선제 배치.
6. **비즈니스 톤**: 크로스셀링(펀드·ISA 유도) 뉘앙스 금지 → "중립적 대안 안내". 불완전판매 감점 리스크 차단.

## 5. 범위

**IN — 반드시 완성**

- **포지션 재구성 엔진**: 거래내역 + pykrx 일봉 → 일별 보유량·평단·미실현손익 타임라인
- **편향 지표 3종**
  - ① 처분효과 DE = PGR − PLR (Odean 1998)
  - ② 물타기 지수 (미실현 −5% 이하에서 추가매수 비중 + 해당 건 결말 평균)
  - ③ 추격매수 계수 (매수 직전 5일 수익률, 급등 후 매수 비중)
- **브레이크 룰 3종** (트리거 조건 → 개입 문구 → 백테스트 판정 기준)
- **백테스트 v1 → 수치 헤드라인** ("적용 시 손실 X% 감소") — **이번 프로젝트의 승부처**
- **웹 MVP** (FastAPI + 진단 리포트 + 개입 UI) + 배포
- CSV 지원 양식: **KB증권 1종만** (공동주최사)

**OUT — 기획서 로드맵으로만 언급**

지표 ④손절지연비 ⑤회전율 ⑥패닉·복수매매 / 키움 양식 / 유사 과거매매 top-3 / MyData 실연동

## 6. 파이프라인과 역할

```
KB export ─[B 파서]→ 표준 거래내역 ─[A 엔진]→ 포지션 타임라인 ─┬→ [C·B 지표 3종] → 진단 리포트
                                                          ├→ [C 브레이크 룰] → 주문 개입(게이지·워터폴)
                                                          └→ [D 백테스트] → net 수치 헤드라인
                                  (전 구간을 D의 API·배포·UI가 감싸서 "실작동 웹서비스"로 제출)
```

역할은 백엔드/프론트 같은 레이어가 아니라 **파이프라인 한 토막씩**이다.

| 담당 | 역할 | 소유 폴더 |
|---|---|---|
| **A** (리더) | 데이터 계약 + 포지션 재구성 엔진, 통합 지휘, 기획서 편집 | `core/schema.py`, `core/engine/` |
| **B** | KB 파서 + 합성 페르소나 생성기 (→ 지표 ②③ 인수) | `core/parser/`, `core/synth/` |
| **C** | 지표 ① 처분효과 (지표 표준 패턴 확립) → 브레이크 룰 3종 | `core/metrics/`, `core/rules/` |
| **D** | 백테스트 하네스 + API·배포·UI·데모 | `core/backtest/`, `api/`, `web/`, `deploy/` |

**서로 기다리지 않기 위한 장치 2개**

1. **fixture 먼저** — 상류 모듈 완성 전엔 합성 fixture 로 개발한다
2. **스키마 문서가 진실** — 모듈 간 데이터 형태는 `docs/schema.md` 에 적힌 것만 유효.
   바꾸려면 코드가 아니라 문서부터 PR

## 8. 현재 상태 (2026-08-27)

**🚨 최우선 블로커: 실 거래내역이 0건이다.**

계좌는 개설했으나 국내주식 매매 이력이 없다. KB HTS 화면 3종(0112·0330·0377)의 포맷은
전부 확정했고 파서도 완성됐지만, **넣을 데이터가 없다.**

→ 개발·데모는 **`core/synth` 합성 페르소나**로 간다. 이게 우회로가 아니라 메인 도로다.
   파서는 실데이터가 오면 바로 붙도록 준비만 된 상태.
   실데이터가 필요하면 기존 계좌에 매매 기록이 있는 팀원을 찾는 게 가장 빠르다.

| 모듈 | 상태 |
|---|---|
| `core/parser` | ✅ KB 화면 3종 매핑, 테스트 30개 |
| `tools/inspect_export.py` | ✅ 증권사 파일 구조 덤프 + 개인정보 마스킹 |
| `core/synth` | ✅ 합성 페르소나 5종 + pykrx 원시 시세 캐시(`prices.py`). Monte Carlo로 편향 신호 검증 |
| `docs/schema.md` | 원시 시세 인터페이스(§5) 확정. **A 확정 필요 — §6 미결 3개** (최대 병목) |
| `core/engine` · `core/metrics` · `core/rules` · `core/backtest` · `api/` | ⬜ |
| `web/` | 스켈레톤은 `lovulive` 브랜치 (Next.js) |
